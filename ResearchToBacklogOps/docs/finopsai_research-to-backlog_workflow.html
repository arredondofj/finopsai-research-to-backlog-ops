Product Owner Workflow

Use this workflow to route product-relevant research sources into the right lane, produce consistent artifacts, map ideas to FinOpsAI when appropriate, and gate ClickUp-ready card drafts.

Workflow Scope
Implemented Guide

RESEARCH_WORKFLOW_USAGE.md is now the controlling workspace guide for source taxonomy, routing, artifact names, repo-mapping categories, roadmap-fit statuses, and the ClickUp card-candidate gate.

Separate Lanes

Each source type keeps its own intake rules and risk checks so transcripts, GitHub repos, domain content, requirements, and workflow material are not forced through the same analysis path.

Workflow Usage
Use this workflow when source material needs to become a researched, assessed, mapped, or backlog-candidate artifact for FinOpsAI. Start in CodeX unless a step explicitly belongs in another tool.
Note: The shared standards now live in RESEARCH_WORKFLOW_USAGE.md; this visual shows how to use them operationally.
  • Workflow Usage Guide: CodeX is the primary interface for registering sources, selecting lanes, producing research artifacts, mapping ideas to FinOpsAI, assigning roadmap-fit status, and drafting ClickUp-ready card candidates. Use another tool only when that tool owns the action, such as ClickUp for publishing cards, a browser or Git tooling for approved external repo/source access, or FinOpsAI workflow docs for Product Design and Product Development handoff.
  • When to use: Use this harness for YouTube transcripts, GitHub repositories, business requirements, accounting/bookkeeping domain content, and product development workflow material. If the source is only a transcript cleanup request, use the transcript pipeline directly through PIPELINE_USAGE.md.

Workflow Phases
Phase 1 Intake And Analyze 2 steps ▶
◆
Purpose & scope: Phase 1 establishes the research run and produces the source-facing analysis needed to decide whether further FinOpsAI evaluation is warranted. It begins with intake and routing to capture source context, select the correct lane, set the expected artifact, and confirm workflow boundaries before any durable analysis begins. It then runs the selected lane-specific analysis to produce the appropriate research artifact for the source.

Phase 1 does not perform FinOpsAI applicability mapping, assign roadmap-fit status, approve work for implementation, or generate ClickUp-ready card drafts. Those actions belong to later phases and should only occur after Phase 1 is complete and its gates have passed.
